## 1. 六个必须先定的问题

1. **信息边界**：公平（只给玩家能看到的）／全知（抽牌顺序、敌人下一步）／混合。
   这决定它是"教练"还是"外挂"，也决定规则学到的东西能不能迁移到真人视角。
2. **辅助形态**：只在关键点提示／每步完整建议／教练模式（先问你）／自动执行。
   自动执行是另一个量级的工程（输入注入、动画等待、异常恢复），不要混在 MVP 里。
3. **如何验证"规则变好了"**：没有验证的自动优化 = 随机漂移。6 局数据什么也证明不了。
4. **记录粒度**：战略层游戏已经帮你记了，别重复造；真正缺的是战斗内逐回合与"未选项"。
5. **知识来源**：卡牌数值、关键词、敌人招式必须来自游戏数据；LLM 记忆里的 StS2 内容是幻觉重灾区。
6. **成本与延迟**：战斗内只能用本地规则（<150ms）；LLM 只放在回合结束、局末、离线复盘。

## 2. 优化点

### A. 数据与知识（性价比最高，先做）

- **A1 用 `.run` 做零成本回填**：不写一行 mod，就能做出"每层掉血/金币效率/卡牌取舍/死亡点分布"的 dashboard 和基线。
- **A2 从 `sts2.dll` + `.pck` 抽结构化卡库**：卡牌/遗物/药水/敌人/事件，含中英文名、升级值、稀有度、费用、关键词。按版本生成，更新时自动 diff。
- **A3 抽敌人意图/招式表**：从反编译代码提取 move 状态机，才能精确算"下回合挨多少"，而不是让模型猜。
- **A4 定义唯一的 `FeatureVector` 契约**：战斗、卡组、路线、经济四类特征，adapter / 规则 / LLM 三方共用，带 schema 版本。
- **A5 实例状态而非模板值**：卡牌 `props`、遗物计数器、附魔、临时升级都要进状态；否则 `THE_SCYTHE` 这类成长卡会算错。
- **A6 中英双轨**：内部全用 ID，展示用本地化名；强制 UTF-8，避免"閿嬪埄"。
- **A7 召唤物建模**：Osty 这类单位既是"敌人列表成员"又是玩家资源，解析时必须单独归类。
- **A8 先验来源分层**：社区 tier list / 旧作知识只做先验，标 `provenance`，可被本地数据推翻。

### B. 采集与记录

- **B1 两层数据 join**：`.run` 负责战略层，mod JSONL 负责战斗层，用 `run_id + floor + room` 对齐，不重复记录。
- **B2 事件溯源**：append-only，每回合一个快照（差分压缩）；`run_start → floor_enter → combat_start → turn_start → action → advice → combat_end → reward → …`。
- **B3 记录 RNG 与隐藏信息，但打可见性标签**：seed、抽牌堆顺序、敌人意图；`visibility: fair|omniscient`。事后分析可用全知，实时建议只能用 fair。
- **B4 记录"建议 vs 实际"**：引擎推荐了什么、玩家选了什么、犹豫了多久（悬停/取消）。这是最有价值的偏好与纠错数据。
- **B5 记录可执行目标**：卡牌 index、敌人 id、地图节点 id，让建议能高亮、能回放、以后能一键执行。
- **B6 记录"未选项"**：事件/商店/奖励的完整候选；现在 `.run` 只记事件被选项，无法评估事件 EV。
- **B7 崩溃安全**：回合边界 flush、原子写、轮转；全部异步，别让 IO 卡帧。
- **B8 体积控制**：zstd + 差分 + 卡牌定义去重；一局战斗层控制在几百 KB。

### C. 规则引擎

- **C1 规则即数据**：YAML/JSON，带 `id / scope / priority / when / score / advice / confidence / provenance / version`；代码只做解释器。
- **C2 三阶段**：硬约束（斩杀、必防、能量可行性）→ 软打分（权重）→ 仲裁（优先级 + tie-break）。永远输出 top-3 + 分数分解。
- **C3 把建议当排序问题**：不做"唯一正确答案"，做候选打分；这样天然支持"差一点"的解释和后续学习。
- **C4 覆盖率与冲突检测**：统计"无规则命中"的决策点（驱动补规则）、互相矛盾的规则、从不触发的死规则。
- **C5 规则单元测试**：fixture 状态 → 期望建议；LLM 提的每条 patch 必须过测试才能进 staging。
- **C6 通用资源抽象**：energy / star / summon / orb / poison / forge / enchant，避免每加一个角色重写引擎。
- **C7 分层组织**：通用原则 / 角色 / 流派 / 敌人 / 幕；别做成一张大表。
- **C8 先别造 DSL**：先用"Python 函数 + YAML 阈值"跑 20 条规则，模式稳定后再抽 DSL；提前抽象必返工。
- **C9 决策点分类学**：`combat_turn / card_reward / map_node / shop / rest / event / relic / potion / boss_prep`，每类一个评估器，状态需求不同。
- **C10 建议去噪**：同一决策只推一次；战斗中每次 action 后重算，奖励界面只算一次。

### D. 战斗内智能（差异化核心）

- **D1 本回合搜索求解**：手牌 ≤10、能量 ≤4，枚举出牌序列 + beam search/剪枝，目标 = 击杀 > 少掉血 > 留资源 > 少弃牌。比任何启发式强，而且能直接说"最优序列是 …"。
- **D2 多回合前瞻**：敌人意图模式 + 抽牌分布期望，回答"这回合该贪还是该稳"。
- **D3 药水纳入搜索**：很多新手死于"舍不得喝"；把药水当 0 费即时资源。
- **D4 不确定性**：fair 模式下按牌库分布算期望与最坏情况，给置信度而不是拍脑袋。
- **D5 可避免伤害（ADA）**：每场战斗后用求解器回放，算出"本来可以少掉多少血"。这是最好的教学指标，也是规则的稠密奖励。
- **D6 可视化优先于文字**：把"这回合预计掉 14 血""有斩杀"直接画出来，比一段建议有效。
- **D7 实现位置**：战斗数学放 C#（能直接读游戏对象/效果），战略规则放 Python；不要为了统一而把战斗求解搬到 Python 重写一遍卡牌效果。

### E. 战略层（漏得最多的地方）

- **E1 地图 DP**：整层地图开局可见，是 DAG 上的期望值优化；按 HP/金币/卡组强度/精英准备度给每条路线打分，而不是"精英越多越好"。
- **E2 卡牌边际价值**：`base_prior + 流派协同 + 当前幕/Boss 针对性 + 曲线/冗余惩罚 + 机会成本`，不是静态 tier list。
- **E3 卡组诊断**：流派识别、胜利条件是否存在、费用曲线、防御密度、过牌、AOE、scaling；输出"这套牌缺什么"。
- **E4 经济模型**：商店价格（含 Membership Card 等修正）、删牌优先级、攒钱阈值、买药时机。
- **E5 休息点 EV**：升级 vs 回血 vs 其他，按"接下来 3 层预期伤害"算，而不是看当前血量拍脑袋。
- **E6 事件 EV**：需要 B6 的未选项数据；未知事件给探索价值，不装作确定。
- **E7 精英/Boss 准备度**：给出"你现在打这个精英的估计胜率/预计掉血"；样例局第 9 层就是典型误判。
- **E8 幕间门槛**：进 Act 2/3 前检查 AOE、scaling、防御密度、药水储备。
- **E9 开局与 Boss 遗物**：Neow 选项、Act 过渡三选一，影响整局，值得单独建模。

### F. LLM 复盘

- **F1 不要喂全量日志**：先本地算 digest（指标 + top-K 决策点，按 EV loss/不确定性排序），再喂模型。
- **F2 结构化输出**：`findings[] / evidence_event_ids[] / root_cause / rule_patch / confidence`；程序校验引用的 event id 真实存在，防幻觉。
- **F3 两段式**：分析 → 批判（devil's advocate）→ 合并；flash 足够便宜。
- **F4 分层复盘**：单局（战术）→ 每晚/每周（模式）→ 赛季（规则架构该不该改）。
- **F5 最多 3 条可执行建议**：每条必须落到具体决策点 + 具体改法；泛泛而谈的复盘没人看。
- **F6 Prompt 缓存**：规则书 + 卡库作为稳定前缀（cache hit 价格差 50 倍）；夜间 off-peak 批量跑。
- **F7 成本**：单局 digest 约几万 token，flash 离峰价下 **单局 < 1 美分**；设日上限、超时降级到本地规则。
- **F8 复盘质量评估**：玩家评分 + 建议采纳率 + 改完之后指标是否真的变好；否则只是"听起来有道理"。
- **F9 复盘要可视化**：时间轴 + HP/金币曲线 + 决策点跳转；纯文字复盘记不住。

### G. 规则进化闭环（最难，但这是"越玩越强"的关键）

- **G1 分级自动化**：L0 文本建议（人改）→ L1 结构化 patch（人审）→ L2 沙盒回测 → L3 自动合并（严格 gate）。先停在 L1。
- **G2 反事实回测**：用完整状态 + RNG 做 headless 重放，或至少做"决策点评分"而不是只看输赢。
- **G3 稠密奖励**：一局只有 win/lose，标签太稀疏；用每场掉血、每层金币、精英胜率、ADA 做中间信号。
- **G4 影子模式**：引擎先预测、玩家照自己打、事后比较预测 vs 实际；既校准模型又不干扰。
- **G5 统计门槛**：样本 < N 不改规则；按角色/难度分层；给置信区间，别把 2 局当规律。
- **G6 防过拟合**：holdout（按 seed/角色）、每轮改动上限、必须能 rollback、规则变更日志带证据链接。
- **G7 可证伪假设**：让模型提"我认为 Act 2 前应优先删打，因为 …"，再用数据验证；不要让它直接调权重。
- **G8 规则溯源**：每条规则记录来源（手写/统计/LLM）与证据 run id，方便清理和解释。
- **G9 冷启动**：6 局不够。用 `.run` 历史 + 社区先验 + 自我对弈（可选）三种来源混合，并明确标注可信度。

### H. 交互与产品

- **H1 四档模式**：提示（只在 EV loss 大时说话）／完整／教练（先问你，再揭晓）／自动。
- **H2 双屏**：游戏内极简 overlay（高亮 + 一行字）+ 外部 dashboard（详细解释、复盘），比全塞进游戏稳。
- **H3 建议可点**：高亮卡牌/敌人/地图节点；"一键执行"放最后做。
- **H4 信任校准**：显示置信度、理由、以及"我可能错"；允许"我不同意"并记录为标签。
- **H5 防依赖**：教练模式、延迟揭示、周报"你进步了吗"；别把游戏玩成看 AI 打。
- **H6 中文字体**：Godot 默认字体没有 CJK，overlay 会出豆腐块；要么带 Noto，要么用系统字体。
- **H7 不打断**：LLM 永远不同步阻塞战斗；API 失败静默降级。
- **H8 情绪设计**：复盘先讲做对的，再讲 1-3 个改进点；死亡局尤其。
- **H9 可访问性**：字号、透明度、色盲友好、热键可改。

### I. 工程与运维

- **I1 进程分离**：C# mod（采集/UI）↔ 本地服务（规则/LLM/存储），命名管道或 WebSocket；规则热更新不用重启游戏。
- **I2 稳定第一**：所有 hook 包 try/catch，全局 kill switch，observe-only 不改游戏状态；mod 崩了不能带崩存档。
- **I3 版本适配层**：EA 更新频繁，adapter 隔离 + 启动自检 + 版本 pin；API 挂了至少还能靠 `.run` 做赛后复盘。
- **I4 测试**：headless 回放、规则 golden tests、CI 对新 assembly 冒烟。
- **I5 观测**：结构化日志 + 回放查看器（时间轴、状态 diff、建议 vs 实际、EV loss 热力图）。
- **I6 本地安全**：HTTP 只绑 `127.0.0.1` + token；API key 不落日志；不上传对局。
- **I7 合规**：不打包游戏资源/反编译代码；遵守 EULA；发 Workshop 再单独评估。
- **I8 性能**：日志压缩、差分、异步；别每帧序列化整个状态。

### J. 评估体系

- **J1 指标树**：结果（胜率/到达层）→ 过程（每幕掉血、金币效率、精英胜率、药水使用率）→ 决策（EV loss、建议采纳率）→ 学习（教练测试）。
- **J2 基线**：自己的 6 局历史、规则 v1、纯 LLM、无辅助。
- **J3 校准**：预测胜率 vs 实际胜率（Brier score）；不校准的置信度不如不显示。
- **J4 专家标注集**：手标 50 个决策点，衡量引擎 precision；版本间回归。

## 3. 我认为最值钱的 5 件事

1. **`.run` 回填 + dashboard**：零成本、立刻有用，还能当基线。
2. **本回合精确求解器**：战斗建议从"经验之谈"变成"算出来的"，且能算 ADA。
3. **地图 DP**：战略层最大的漏点，人类普遍凭感觉走。
4. **结构化复盘 + 证据引用 + patch 审核**：让"越玩越强"可复现，而不是每次换一套说辞。
5. **公平信息边界 + 影子模式**：保证学到的是"人能做到的"，且能验证。

## 4. 反模式（明确不做）

- 一上来做自动打牌：输入注入 + 动画等待 + 异常恢复 = 无底洞。
- 用 LLM 做实时战斗决策：慢、贵、不稳定、会编。
- 把 tier list 当规则：不同幕、不同卡组、不同 Boss 下结论相反。
- 只记结果不记决策：无法归因，复盘只能讲故事。
- 让 LLM 直接改规则文件：规则漂移、不可复现、无法回滚。
- 拿 6 局数据调参：过拟合到噪声。
- 全知视角给建议：人类学不会，还会觉得"这游戏没意思"。
- 每步都弹建议：玩家第一件事就是关掉它。
- 改存档/改游戏状态：坏档与封号风险，且违背"辅助"定位。

## 5. 建议里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 | mod 加载验证 + 状态快照 + 战斗 JSONL | 游戏内能看到一行实时状态；日志能在对局后解析 |
| M1 | 卡库/敌人表 + 伤害数学 + 战斗建议（fair）+ 卡牌奖励建议 | 建议延迟 <150ms；top-3 有分数分解 |
| M2 | `.run` 回填 + 回放查看器 + run digest + LLM 复盘（不改规则） | 每局自动生成复盘；引用全部可校验 |
| M3 | 规则 staging + golden tests + 人工审核 + 回测 | 一条 patch 从提出到合并全链路可回滚 |
| M4 | 本回合求解器 + 地图 DP | ADA 可计算；路线建议有期望值 |
| M5 | 影子模式 + 自动调参（有 gate） | 规则 vN 在 holdout 上不劣于 vN-1 |

## 6. 已定（2026-10-18）

1. **辅助形态**：只提示，玩家自己操作。不做自动执行。
2. **信息边界**：默认**公平模式**——只使用玩家屏幕上能看到的信息（手牌、敌人当前意图、抽牌堆/弃牌堆数量与内容）。抽牌顺序、下一张牌、敌人下下步等隐藏信息只用于**赛后复盘**，不进入实时建议。后续可选加"上帝视角"开关，默认关闭，且日志打标、不计入规则学习。
3. **UI**：游戏内 overlay，不做第二屏。F8 隐藏，F9 手动记录。
4. **预算**：DeepSeek 不设硬上限，但记录每局 token/费用。
5. **目标**：冲 Ascension。建议优先级 = 不犯错 > 赢一局 > 贪上限。
6. **练习模式**：不做同种子重开/回退。
7. **发布**：暂不发布 Workshop。
