# ADR 0001：采用外部只读内存读取

- 状态：已采纳
- 日期：2026-10-18
- 决策者：项目作者

## 背景

需要一个能实时看到完整对局、又不关闭成就的助手。候选方案：

1. **Mod**：官方 `mods/` + Harmony，能力最全。
2. **截图 + OCR/Vision**：进程外，只能看到像素。
3. **进程外只读内存**：ClrMD 读 .NET 对象。

## 决策

采用 **3：进程外只读内存**。

- 不装 mod，成就正常
- 不注入、不写内存、不模拟输入
- 用户明确不做公平性限制，可以看到抽牌顺序等全部内容
- C# 只负责读取/显示/落盘，规则与数学放 Python

## 后果

正面：

- 完整、精确、低延迟（0.5–1.5ms/次）
- 不依赖 UI 布局/OCR
- 成就、存档不受影响

负面：

- 依赖私有字段布局，游戏更新可能失效 → 版本锁 + fail closed
- 需要维护 ClrMD 读取层
- “不作弊”靠产品定位，而不是物理隔离

## 被否方案

### Mod

加载 mod 后游戏进入 `RUNNING MODDED`，成就关闭。与需求冲突。

### 截图 + OCR

- 卡名/意图识别不稳，需要模板/词典/VLM
- 延迟与维护成本高
- 只能看到玩家可见信息（用户已明确不需要此限制）

### 修改内存 / 自动打牌

- 违背“只提示、我来操作”
- 风险高，且会改变游戏体验
